درخت‌های جست‌وجوی متوازن

  • درخت اِی‌وی‌اِل (۱۹۶۲): اولین درخت جست‌وجوی متوازن (جلسۀ ۹).
  • درخت ۲-۳ (۱۹۷۰)، درخت بی (B-tree، ۱۹۷۲) و درخت ۲-۳-۴ درخت‌های جست‌وجوی متوازنی هستند که دودویی نیستند و تعداد فرزندان هر رأس می‌تواند بیشتر باشد.
  • درخت BB[α] (۱۹۷۳) که میزان توازن آن به پارامتر α بستگی دارد.
  • درخت قرمز-سیاه (۱۹۷۸، بر پایۀ ایده‌ای از ۱۹۷۲) که موضوع اصلی این جلسه است.
  • درخت اسپلِی (splay tree، ۱۹۸۵) که پس از هر find رأس پیداشده را با دوران به ریشه می‌آورد تا در صورت دسترسی بعدی به سرعت پیدا شود. این درخت جایزه‌های زیادی برده است و هنوز موضوع پژوهش است.
  • لیست پرشی (skip list، ۱۹۸۹) که داده‌ساختاری بین درخت و لیست است.
  • درخت بلاگردان (scapegoat tree، ۱۹۹۳) که در رئوس حافظۀ اضافه ندارد و هر وقت عمق یک رأس زیاد شد، زیردرخت یکی از اجدادش را از نو به صورت کاملاً متوازن بازسازی می‌کند.
  • تریپ (treap، ۱۹۹۶): ترکیب درخت دودویی جست‌وجو (tree) و هرم (heap) با اولویت‌های تصادفی.

درخت ۲-۳، درخت ۲-۳-۴ و درخت بی

  • در درخت ۲-۳ هر رأس داخلی یا یک کلید و دو فرزند دارد یا دو کلید و سه فرزند. در درخت ۲-۳-۴ هر رأس دو، سه یا چهار فرزند دارد. در هر دو، همۀ برگ‌ها در یک عمق‌اند (کاملاً متوازن).
  • کلیدهای هر رأس مرتب‌اند و کلیدهای زیردرخت iام بین کلید iام و i + 1ام رأس هستند؛ جست‌وجو تعمیم همان جست‌وجوی درخت دودویی است.
  • درج: کلید را در برگ مناسب می‌گذاریم. اگر رأس بیش از حد پر شد (در درخت ۲-۳، سه کلید)، آن را به دو رأس می‌شکنیم و کلید وسط را به پدر می‌فرستیم؛ ممکن است این کار تا ریشه ادامه پیدا کند و اگر ریشه شکسته شد، یک ریشۀ جدید ساخته می‌شود و ارتفاع یکی زیاد می‌شود. پس درخت همیشه کاملاً متوازن می‌ماند.
  • در درخت بی تعداد فرزندان هر رأس (به جز ریشه) بین k و 2k − 1 برای یک پارامتر ثابت k است. درخت بی برای دسترسی کمتر به حافظۀ جانبی (دیسک) طراحی شده است: هر رأس به اندازۀ یک بلوک است و ارتفاع O(logk n).
def btree_find(node, k):
  i = 0
  while i < len(node.keys) and k > node.keys[i]:
    i += 1
  if i < len(node.keys) and node.keys[i] == k:
    return node
  if not node.children:
    return None
  return btree_find(node.children[i], k)

درخت قرمز-سیاه

  • تعریف و خواص درخت قرمز-سیاه:
    • ۱. رنگ هر رأس یا قرمز است یا سیاه.
    • ۲. ریشه سیاه است. رئوس None (برگ‌ها) به جای فرزندانی که وجود ندارند قرار می‌گیرند و سیاه‌اند.
    • ۳. اگر یک رأس قرمز باشد، والد آن (در صورت وجود) سیاه است.
    • ۴. هر مسیر از یک رأس به هر برگ زیردرختش تعداد یکسانی رأس سیاه دارد. این تعداد برای ریشه ارتفاع سیاه (سیاه‌ارتفاع) نامیده می‌شود (رئوس None حساب نمی‌شوند).
  • مثال: درخت قرمز-سیاه زیر و بررسی خواص آن.
  • اثبات متوازن بودن درخت قرمز-سیاه:
    • ۱. رئوس قرمز را با والد خود ادغام می‌کنیم و یک درخت ۲-۳-۴ به وجود می‌آید.
    • ۲. این درخت کاملاً متوازن است و ارتفاعش ارتفاع سیاه b است و هر رأس آن حداقل دو فرزند دارد، پس n ≥ 2b − 1. طبق خاصیت ۳ حداقل نصف رئوس هر مسیر سیاه‌اند، پس h ≤ 2b و بنابراین h ≤ 2 log2(n + 1).

درج در درخت قرمز-سیاه

  • مشابه درخت اِی‌وی‌اِل، ابتدا درج را به صورت عادی انجام می‌دهیم و رأس جدید را قرمز می‌کنیم (پس خاصیت ۴ به هم نمی‌خورد)، سپس از پایین به بالا درخت را تصحیح می‌کنیم.
  • در تصحیح همیشه روی یک رأس قرمز هستیم که والد آن نیز قرمز است (تنها خاصیتی که ممکن است برقرار نباشد خاصیت ۳ است). چون ریشه سیاه است، پدربزرگ وجود دارد و سیاه است.
    • ۱. اگر عمو (برادر پدر) قرمز باشد، پدر و عمو را سیاه و پدربزرگ را قرمز می‌کنیم و کار را از پدربزرگ ادامه می‌دهیم.
    • ۲. اگر عمو سیاه باشد نیاز به دوران داریم: اگر مسیر خود-پدر-پدربزرگ زیگزاگی باشد دو دوران و وگرنه یک دوران. این دوران‌ها کاملاً مشابه درخت اِی‌وی‌اِل است. علاوه بر دوران، رأسی که جای پدربزرگ آمده سیاه و پدربزرگ قرمز می‌شود و کار تمام است.
  • در پایان ریشه را سیاه می‌کنیم. پس درج O(log n) تغییر رنگ و حداکثر دو دوران دارد.
  • در کد زیر insert درج درخت دودویی جست‌وجو (جلسۀ ۸) و left_rotate و right_rotate همان دوران‌های جلسۀ ۹ هستند (به‌روزرسانی ارتفاع در آن‌ها اینجا لازم نیست). node.red رنگ رأس است.
def is_red(node):
  return node is not None and node.red

def rb_insert(T, k):
  if T.root is None:
    T.root = new_node(key=k, parent=None, left=None, right=None)
    node = T.root
  else:
    node = insert(T.root, k)
  node.red = True
  fix_up(T, node)

def fix_up(T, node):
  while is_red(node.parent):
    p = node.parent
    g = p.parent
    uncle = g.right if p is g.left else g.left
    if is_red(uncle):              # case 1: recolor
      p.red = uncle.red = False
      g.red = True
      node = g
    else:                          # case 2: rotate
      if p is g.left:
        if node is p.right:        # zigzag
          left_rotate(T, p)
          node, p = p, node
        right_rotate(T, g)
      else:
        if node is p.left:
          right_rotate(T, p)
          node, p = p, node
        left_rotate(T, g)
      p.red = False
      g.red = True
  T.root.red = False
  • مثال: اجرای خط به خط درج کلید ۴ در درخت بالا. رأس‌های قرمز و سیاه به رنگ خودشان‌اند و نام متغیرهای کد بالای رأس‌ها آمده است. در این مثال هم حالت ۱ (تغییر رنگ) و هم حالت ۲ با زیگزاگ (دو دوران) پیش می‌آید.
  • درخت قرمز-سیاه در مقایسه با درخت اِی‌وی‌اِل ممکن است ارتفاع بیشتری داشته باشد، اما حافظۀ اضافۀ کمتری (یک بیت رنگ به جای ارتفاع) استفاده می‌کند. ارتفاع کم برای جست‌وجو بهتر است ولی نگه‌داری آن در درج و حذف سخت‌تر است.
  • حذف در درخت قرمز-سیاه مشابه درج آن نیست و نیاز به درنظر گرفتن چهار حالت دیگر دارد.
  • مرتب‌سازی قرمز-سیاه نیز مثل مرتب‌سازی اِی‌وی‌اِل در O(n log n) تعریف می‌شود.
