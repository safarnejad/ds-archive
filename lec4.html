جلسۀ چهارم: مرتب‌سازی درجی و ادغامی

مطالعۀ بیشتر: ۱-۳، ۲-۳ از قدسی و ۲ از CLRS

  • اولین جلسه با موضوع مرتب‌سازی.
  • تعریف دقیق مسئلۀ مرتب‌سازی: ورودی دنباله‌ای از n عنصر و خروجی جایگشتی از آن‌ها که به ترتیب غیرنزولی باشد.
  • کاربردهای مرتب‌سازی:
    • در حوزه‌های مختلف شامل سیستم‌عامل، پایگاه داده، رندر سه‌بعدی، فشرده‌سازی و …
    • به عنوان گام اول الگوریتم‌های دیگر، مثل مرور کردن اتفاقات ثبت‌شده در چند فایل به ترتیب وقوع.

مرتب‌سازی حبابی

  • هر بار دو عنصر مجاور را که به ترتیب نیستند جابه‌جا می‌کنیم.
  • به هر جفت (i, j) با i < j و A[i] > A[j] یک وارونگی می‌گوییم. هر جابه‌جایی دو عنصر مجاور دقیقاً یک وارونگی را از بین می‌برد، پس تعداد جابه‌جایی‌ها برابر تعداد وارونگی‌ها و حداکثر n(n − 1)/2 است.
def bubble_sort(A):
  for i in range(len(A)):
    for j in range(len(A) - 1 - i):
      if A[j] > A[j + 1]:
        A[j], A[j + 1] = A[j + 1], A[j]

مرتب‌سازی درجی

  • ایده: کلید را از عضو اول به عضو آخر حرکت می‌دهیم. در هر مرحله اعضای قبل از کلید مرتب‌اند و عنصری را که کلید روی آن است در این زیرآرایۀ مرتب درج می‌کنیم.
def insertion_sort(A):
  for i in range(1, len(A)):
    j = i
    while j > 0 and A[j - 1] > A[j]:
      A[j - 1], A[j] = A[j], A[j - 1]
      j -= 1
  • تحلیل زمانی: T(n) را زمان اجرای الگوریتم در بدترین حالت برای ورودی‌های به اندازۀ n کلمه تعریف می‌کنیم. برای اثبات T(n) = Θ(n2) ثابت می‌کنیم O(n2) و Ω(n2) است.
    • کلید n بار جابه‌جا می‌شود و در هر مرحله O(n) جابه‌جایی انجام می‌شود، پس کل عملیات O(n2) است.
    • اگر ورودی به صورت نزولی مرتب باشد، زمان اجرا Ω(n2) است.
    • در واقع زمان اجرا Θ(n + I) است که I تعداد وارونگی‌هاست.
  • مرتب‌سازی درجی دودویی: اگر در مدل محاسبات هزینۀ مقایسه بیشتر از جابه‌جایی باشد، مکان کلید را با جست‌وجوی دودویی پیدا می‌کنیم و سپس با همان تعداد جابه‌جایی قبل آن را درج می‌کنیم. تعداد مقایسه‌ها Θ(n log n) و تعداد جابه‌جایی‌ها Θ(n2) است.

تقسیم و حل و مرتب‌سازی ادغامی

  • رویکرد تقسیم و حل: ۱. تقسیم مسئله به چند زیرمسئله، ۲. حل هر زیرمسئله به صورت بازگشتی، ۳. ادغام نتایج برای حل مسئلۀ اصلی.
  • زمان آن به صورت T(n) = a T(n/b) + f(n) است که با روش‌های جلسۀ قبل حل می‌شود.
  • مرتب‌سازی ادغامی: آرایه را به دو نیمه تقسیم می‌کنیم، هر نیمه را بازگشتی مرتب می‌کنیم و دو نیمۀ مرتب را ادغام می‌کنیم.
def merge(L, R):
  A, i, j = [], 0, 0
  while i < len(L) or j < len(R):
    if j == len(R) or (i < len(L) and L[i] <= R[j]):
      A.append(L[i])
      i += 1
    else:
      A.append(R[j])
      j += 1
  return A

def merge_sort(A):
  if len(A) <= 1:
    return A
  mid = len(A) // 2
  return merge(merge_sort(A[:mid]), merge_sort(A[mid:]))
  • رابطۀ بازگشتی T(n) = 2T(n/2) + Θ(n) و با درخت بازگشت T(n) = Θ(n log n).
  • مرتب‌سازی ادغامی درجا (in place) نیست و Θ(n) حافظۀ اضافه می‌خواهد.
  • چون در merge برای عناصر مساوی اول از L برمی‌داریم، مرتب‌سازی ادغامی پایدار است: ترتیب عناصر با کلید مساوی حفظ می‌شود.

مقایسۀ زمان واقعی اجرا

  • مرتب‌سازی درجی در زبان C: حدود 0.01n2 μs.
  • مرتب‌سازی درجی در پایتون: حدود 0.2n2 μs.
  • مرتب‌سازی ادغامی در پایتون: حدود 2.2n log2 n μs.
  • در این پیاده‌سازی‌ها پایتون حدود ۲۰ برابر کندتر است، ولی الگوریتم سریع‌تر برای n ≥ 4000 این کندی را جبران می‌کند.
  • برای n < 67 در پایتون مرتب‌سازی درجی از مرتب‌سازی ادغامی بهتر عمل می‌کند!

برتری‌های مرتب‌سازی درجی نسبت به ادغامی

  • ۱. حافظۀ اضافه مصرف نمی‌کند. برای کم کردن حافظۀ اضافۀ مرتب‌سازی ادغامی، مرتب‌سازی ادغامی درجا ارائه شده است که حافظۀ اضافۀ ثابت دارد، ولی ۲ تا ۳ برابر کندتر است و در عمل استفاده نمی‌شود.
    • مرتب‌سازی درجی با تنها یک متغیر اضافه (اندیس) هم قابل پیاده‌سازی است. این روش را دکتر سربازی‌آزاد برای اولین بار با نام stupid sort معرفی کرد و بعداً با نام gnome sort شناخته شد.
    def gnome_sort(A):
  i = 0
  while i < len(A):
    if i == 0 or A[i - 1] <= A[i]:
      i += 1
    else:
      A[i - 1], A[i] = A[i], A[i - 1]
      i -= 1
  • ۲. وقتی ورودی (تقریباً) مرتب است، مرتب‌سازی درجی زمان Θ(n) دارد ولی مرتب‌سازی ادغامی همچنان Θ(n log n).

مرتب‌سازی تیم

  • مرتب‌سازی در پایتون، اندروید و جاوا (برای مرتب‌سازی اشیا و نه اعداد) با مرتب‌سازی تیم (TimSort) انجام می‌شود که ترکیبی از مرتب‌سازی درجی و ادغامی است.
  • ایدۀ اصلی آن در سال ۱۹۹۳ منتشر شد و تیم پیترز در سال ۲۰۰۲ آن را برای پایتون طراحی کرد. در ابتدا روی این‌که طراحی آن خارج از فضای آکادمیک انجام شده تبلیغ زیادی شد، ولی در سال ۲۰۱۵ (پس از ۱۳ سال) در تلاش برای اثبات صوری درستی آن یک باگ در آن پیدا شد.
  • روش کار: روی آرایه حرکت می‌کند و قسمت‌های از پیش مرتب (صعودی یا نزولی) را پیدا می‌کند و قسمت‌های نزولی را برعکس می‌کند. قسمت‌های کوتاه‌تر از حدود ۶۴ عنصر را با مرتب‌سازی درجی دودویی بلندتر می‌کند (دلیلش در مقایسۀ زمان واقعی اجرا آمد) و سپس این قسمت‌ها را با ادغام به هم می‌چسباند.
