واسط مجموعه‌های مجزا

  • عملیات: ایجاد مجموعۀ جدید (make_set)، ادغام دو مجموعه (union) و پیدا کردن مجموعۀ یک عنصر (find_set).
  • به جای نام‌گذاری مجموعه‌ها، برای هر مجموعه یک عنصر نماینده در نظر می‌گیریم. find_set(x) نمایندۀ مجموعۀ x را برمی‌گرداند و دو عنصر هم‌مجموعه‌اند اگر و تنها اگر نمایندۀ یکسان داشته باشند.
  • برای سادگی فرض می‌کنیم عناصر ۰ تا n − 1 هستند و همه از ابتدا در مجموعه‌های تک‌عضوی‌اند.

ایدۀ اول: اشاره به نماینده

  • همۀ عناصر مجموعه مستقیماً به نمایندۀ مجموعه اشاره کنند. پیدا کردن مجموعۀ یک عنصر در O(1) انجام می‌شود، ولی ادغام ممکن است O(n) طول بکشد.
  • اگر همیشه مجموعۀ کوچک‌تر را در مجموعۀ بزرگ‌تر ادغام کنیم، با تحلیل سرشکن هزینۀ هر ادغام لگاریتمی است: هر بار که اشاره‌گر یک عنصر عوض می‌شود، اندازۀ مجموعۀ آن دست کم دو برابر می‌شود، پس اشاره‌گر هر عنصر حداکثر ⌊log2 n⌋ بار تغییر می‌کند و n − 1 ادغام در کل O(n log n) طول می‌کشد.
def union_small_large(rep, members, x, y):
  x, y = rep[x], rep[y]
  if x == y:
    return
  if len(members[x]) < len(members[y]):
    x, y = y, x
  for z in members[y]:
    rep[z] = x
  members[x] += members[y]
  members[y] = []

# rep = list(range(n)); members = [[i] for i in range(n)]

ایدۀ دوم: جنگل

  • لازم نیست هر عنصر مستقیماً به نماینده اشاره کند، کافی است با دنبال کردن اشاره‌گرها (parent) به نماینده برسیم. هر مجموعه یک درخت است و نماینده ریشۀ آن است.
  • ادغام (وقتی نماینده‌ها مشخص باشند) در O(1) انجام می‌شود، چون کافی است نمایندۀ یک مجموعه را به نمایندۀ دیگری اشاره دهیم. ولی پیدا کردن نماینده ممکن است طول بکشد.
  • دو ایده برای بهبود عملکرد این داده‌ساختار:
    • ۱. فشرده‌سازی مسیر (path compression): وقتی مجموعۀ یک عنصر را پیدا می‌کنیم، همۀ عناصر مسیر را مستقیماً به نماینده اشاره می‌دهیم.
    • ۲. اتحاد بر اساس مرتبه (union by rank): مجموعۀ با مرتبۀ (حداکثر ارتفاع) کمتر را به مجموعۀ با مرتبۀ بیشتر وصل می‌کنیم. از واژۀ ارتفاع استفاده نمی‌کنیم، چون فشرده‌سازی مسیر ارتفاع را تغییر می‌دهد و مرتبه فقط یک کران بالا برای آن است.
def make_set(parent, rank, x):
  parent[x] = x
  rank[x] = 0

def find_set(parent, x):
  if x != parent[x]:
    parent[x] = find_set(parent, parent[x])
  return parent[x]

def union(parent, rank, x, y):
  x, y = find_set(parent, x), find_set(parent, y)
  if x == y:
    return
  if rank[x] < rank[y]:
    parent[x] = y
  else:
    parent[y] = x
    if rank[x] == rank[y]:
      rank[x] += 1

در اجرای زیر روی هشت عنصر چند اتحاد و یک پیدا کردن انجام می‌شود؛ اشاره‌گرهایی که فشرده‌سازی مسیر عوض می‌کند نارنجی‌اند.

زمان اجرا و تابع آکرمان

  • زمان اجرای m عمل روی این داده‌ساختار O(m α(n)) است، یعنی هر عمل به صورت سرشکن O(α(n))، که α وارون تابع آکرمان است (تارجان، ۱۹۷۵). این کران بهینه است: فردمن و ساکس (۱۹۸۹) کران پایین Ω(α(n)) را برای هر داده‌ساختار مجموعه‌های مجزا ثابت کردند.
  • تعریف تابع آکرمان (به شکل CLRS): برای j ≥ 1
    A0(j) = j + 1
    Ak(j) = Ak−1(j+1)(j)
    که Ak−1(j+1) یعنی j + 1 بار اعمال پشت سر هم Ak−1.
  • داریم A1(j) = 2j + 1 و A2(j) = 2j+1(j + 1) − 1. پس A1(1) = 3، A2(1) = 7، A3(1) = A2(7) = 2047 و
    A4(1) = A3(2047) ≫ A2(2047) = 22048 · 2048 − 1 > 16512 ≫ 1080
    که از تعداد اتم‌های جهان قابل مشاهده بسیار بیشتر است.
  • تعریف دقیق: α(n) = min{k : Ak(1) ≥ n}. پس برای همۀ کاربردهای عملی α(n) ≤ 4 است.
  • اثبات این زمان (در CLRS) با روش تابع پتانسیل در تحلیل سرشکن انجام می‌شود که در ادامه می‌آید. تابع پتانسیلی که در این اثبات استفاده شده نشان می‌دهد تعریف چنین تابعی اصلاً ساده نیست.

تحلیل سرشکن

  • تحلیل سرشکن (amortized analysis) معیار مهمی در تحلیل داده‌ساختارهاست، زیرا در بسیاری از کاربردها مهم این است که عملیات داده‌ساختار در مجموع چقدر طول می‌کشند و طولانی شدن یک عمل در درجۀ دوم اهمیت است.
  • محیط این تحلیل یک داده‌ساختار و دنباله‌ای از عملیات روی آن است و (در ساده‌ترین شکل) میانگین هزینۀ عمل‌ها هزینۀ سرشکن هر عمل است. این میانگین روی دنبالۀ عملیات در بدترین حالت است و ربطی به احتمال ندارد.
  • یادآوری دو برابر کردن جدول در آرایۀ پویا (جلسۀ ۵): پس از n درج، تغییر اندازه‌های جدول در مجموع Θ(n) طول می‌کشد، پس هزینۀ سرشکن هر درج Θ(1) است.
  • مثال دیگری که با هر چهار روش زیر بررسی می‌کنیم: پشته‌ای با سه عمل push(x)، pop() و multipop(k) که k عنصر بالای پشته را حذف می‌کند (یا همه را اگر کمتر از k عنصر باشد). یک multipop ممکن است Θ(n) طول بکشد، ولی می‌خواهیم نشان دهیم هزینۀ سرشکن هر عمل O(1) است.
def push(S, x):
  S.append(x)

def pop(S):
  return S.pop()

def multipop(S, k):
  while S and k > 0:
    S.pop()
    k -= 1

۱. روش تجمیعی

  • روش تجمیعی (انبوهه، aggregate): مجموع هزینه‌ها تقسیم بر تعداد عملیات. فقط برای مسائل ساده کاربرد دارد.
  • مثال پشته: هر عنصر دقیقاً یک بار وارد پشته می‌شود و حداکثر یک بار با pop یا multipop حذف می‌شود. پس هزینۀ n عمل حداکثر 2n و هزینۀ سرشکن هر عمل O(1) است.
  • در حالت کلی‌تر می‌توان به هر عمل یک هزینۀ سرشکن جدا نسبت داد، به این شرط که در هر لحظه مجموع هزینه‌های سرشکن دست کم به اندازۀ مجموع هزینه‌های واقعی باشد. مثلاً در درخت اِی‌وی‌اِل می‌توان هزینۀ هر درج را Θ(log n) و هزینۀ هر حذف را ۰ در نظر گرفت و در واقع هزینۀ حذف هر عنصر را روی درج همان عنصر گذاشت.

۲. روش حسابداری

  • هر عمل می‌تواند علاوه بر هزینۀ اصلی خود، مقدار بیشتری بپردازد و آن را در یک حساب بانکی ذخیره کند، یا بخشی از هزینۀ خود را از حساب برداشت کند، به این شرط که موجودی حساب هیچ‌گاه منفی نشود.
  • مثال آرایۀ پویا: در هر درج بدون تغییر اندازه، علاوه بر ۱ سکۀ خود درج، ۲ سکه ذخیره می‌کنیم. وقتی آرایه از k به 2k بزرگ می‌شود، از آخرین تغییر اندازه k/2 درج انجام شده و k سکه ذخیره شده که هزینۀ کپی k عنصر را می‌پردازد. پس هزینۀ سرشکن هر درج ۳ است.
  • مثال پشته: برای هر push دو سکه می‌پردازیم، یکی برای خود push و یکی را روی عنصر داخل پشته می‌گذاریم. هزینۀ pop و هر حذف در multipop با سکۀ روی همان عنصر پرداخت می‌شود و رایگان است. پس هزینۀ سرشکن هر عمل حداکثر ۲ است.

۳. روش شارژ کردن

  • این روش در مراجع نیامده است: هر عمل می‌تواند بخشی از هزینۀ خود را روی اعمال قبلی شارژ کند. هزینۀ سرشکن هر عمل برابر هزینۀ واقعی آن، منهای هزینه‌ای که روی بقیه شارژ کرده، به علاوۀ هزینه‌ای است که در آینده روی آن شارژ می‌شود (معمولاً هر عمل یا فقط شارژ می‌کند یا فقط شارژ می‌شود).
  • دو برابر کردن آرایه با این روش ساده استدلال می‌شود: هر تغییر اندازه از k به 2k هزینۀ خود را روی k/2 درج بعد از تغییر اندازۀ قبلی شارژ می‌کند و هر درج فقط یک بار و حداکثر ۲ واحد شارژ می‌شود.
  • دو برابر کردن و نصف کردن جدول (جلسۀ ۵) هم با این روش به راحتی بیان می‌شود.
  • معادل روش حسابداری است ولی شهود بیشتری دارد.

۴. روش تابع پتانسیل

  • قوی‌ترین روش تحلیل سرشکن است (اثبات زمان مجموعه‌های مجزا هم با این روش است). حالت کلی‌تر روش حسابداری است که در آن موجودی حساب تابعی از وضعیت داده‌ساختار است.
  • تابع پتانسیل Φ وضعیت داده‌ساختار را به یک عدد نامنفی می‌برد. اگر Di داده‌ساختار بعد از عمل iاُم و ci هزینۀ واقعی آن باشد، هزینۀ سرشکن آن
    ei = ci + ΔΦ = ci + Φ(Di) − Φ(Di−1)
    است. با جمع زدن، Σ ei = Σ ci + Φ(Dn) − Φ(D0). پس اگر Φ(D0) = 0 و Φ ≥ 0، مجموع هزینه‌های سرشکن کران بالایی برای مجموع هزینه‌های واقعی است.
  • پیدا کردن تابع پتانسیل مناسب به هیچ عنوان ساده نیست.
  • مثال پشته: Φ را تعداد عناصر پشته می‌گیریم. برای push داریم ei = 1 + 1 = 2، برای pop داریم ei = 1 − 1 = 0 و برای multipop که k′ عنصر را حذف می‌کند ei = k′ − k′ = 0. پس هزینۀ سرشکن هر عمل O(1) است.
  • مثال شمارندۀ دودویی: هر increment بیت‌های ۱ انتهای عدد را ۰ و یک بیت ۰ را ۱ می‌کند. می‌خواهیم نشان دهیم تعداد تغییر بیت‌ها در هر مرحله به صورت سرشکن O(1) است.
    • اگر تعداد یک‌های سمت راست (انتهای عدد) را تابع پتانسیل بگیریم درست کار نمی‌کند.
    • تعداد کل یک‌های شمارنده را تابع پتانسیل می‌گیریم. اگر increment t بیت ۱ را ۰ کند، هزینۀ واقعی t + 1 و ΔΦ = 1 − t است، پس ei = 2.
def increment(B):  # B[0] is the least significant bit
  i = 0
  while i < len(B) and B[i] == 1:
    B[i] = 0
    i += 1
  if i < len(B):
    B[i] = 1
